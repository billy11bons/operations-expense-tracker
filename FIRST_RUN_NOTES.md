# Первый запуск — этап 2

Дата: 07.09.2026. Первая рабочая версия MVP 0.1.0. Это проверка сборки и базовых действий, не полный отчёт приёмки этапа 3.

## Что реализовано

- Четыре маршрута: Dashboard `/`, Expenses `/expenses`, Tasks `/tasks`, Categories `/settings`.
- Расходы: создание, редактирование, удаление с подтверждением; все поля ТЗ, проверка ввода, фильтры даты/категории.
- Задачи: CRUD, owner, due date, status, priority, note; изменение статуса в списке; отдельные Pending/overdue, исключение Done из просрочки; фильтры статуса/приоритета.
- Недельная сумма в USD, четыре карточки Dashboard, списки последних расходов и задач, требующих внимания.
- Категории: начальный список и добавление уникальных названий.
- Однократные демоданные, localStorage, сохранение после reload; проверка структуры данных и обработка ошибок чтения/записи.
- Базовая адаптивность, диалоги форм и удаления, клавиатурный focus, пустые состояния.

Стек по фактически установленным пакетам: Next.js 16.3.4, React/React DOM 19.2.8, TypeScript 7.0.2, Tailwind CSS 4.3.3. Версии закреплены в package.json и package-lock.json. Среда запуска: Windows, Node.js 22.23.1, npm 10.9.8.

## Как запустить

PowerShell, зависимости уже установлены:

```powershell
Set-Location -LiteralPath 'E:\Prompt\Freelance\Trecker\Case_01_Operations_Expense_Tracker\app'
npm.cmd run dev
```

Адрес: http://127.0.0.1:3000

На момент завершения этапа сервер уже оставлен запущенным. Если порт занят этим сервером, откройте адрес, а не запускайте вторую копию. Для остановки сервера в собственном терминале — Ctrl+C.

При восстановлении проекта из исходников:

```powershell
Set-Location -LiteralPath 'E:\Prompt\Freelance\Trecker\Case_01_Operations_Expense_Tracker\app'
npm.cmd ci
npm.cmd run dev
```

В данной Windows-среде npm потребовал доверенные системные сертификаты. Если установка выдаёт `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, перед `npm.cmd ci` в том же терминале выполните `$env:NODE_USE_SYSTEM_CA='1'`. Проверка TLS не отключалась.

Проверки:

```powershell
npm.cmd test
npm.cmd run build
```

`npm.cmd run start` запускает готовую production-сборку на том же порту после остановки dev-сервера. Отдельный production-сервер в этапе 2 не запускался; проверена именно сборка.

## Реальные проблемы первого запуска и исправления

1. **Доступ к папке в shell.** Песочница блокировала Set-Location в рабочую папку. Первая попытка npm завершилась EPERM без установки в корень. Дальнейшие команды использовали `ErrorActionPreference=Stop`, явную рабочую папку и разрешённое выполнение вне песочницы.
2. **Сертификат npm.** Установка повторяла `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. Исправлено использованием системных CA через `NODE_USE_SYSTEM_CA=1`; зависимости затем установились.
3. **Подписи select.** Первый browser smoke остановился на поиске фильтра Category по точной подписи. У select добавлены явные доступные имена; исправление распространено на Status/Priority и аналогичные поля форм. Повторный smoke прошёл.
4. **Отсутствующая иконка.** В первом проходе зафиксирован один ответ 404; отсутствовал favicon. Добавлен `src/app/icon.svg`; во втором проходе console errors отсутствуют.
5. **Turbopack и временный профиль браузера.** Первая production-сборка упала при попытке прочитать занятый Cookies-файл тестового профиля внутри app. Источник сканирования Tailwind ограничен папкой src; временные файлы браузера перенесены в verification/stage-02/runtime-temp. Повторная production-сборка успешна. Автоматически созданный panic-log перемещён из системного Temp в папку кейса.
6. **Предупреждение о файловой системе.** Next.js сообщил slow filesystem (466 ms). Это предупреждение, запуск и последующая сборка завершились; папка проекта сохранена по требованию пользователя.

Сохранены исходный неуспешный smoke-результат, снимок остановки и лог первой ошибки сборки. Финальная стилизация на этом этапе не выполнялась.
