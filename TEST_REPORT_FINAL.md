# Финальный отчёт этапа 4

Дата: 07.09.2026. Исправлен подтверждённый MVP-баг клавиатурной навигации.

## Feedback и классификация

Пользователь сообщил о необходимости исправить замечание. Диагностика показала: после открытия диалога фокус оказывался на Close, после Escape уходил на body и не возвращался к кнопке вызова.

- Bugs: некорректный начальный фокус и возврат фокуса.
- UX/accessibility: клавиатурная навигация modal dialog.
- Логика, внешний вид и новые пожелания: замечаний не поступало.

## Исправление

В `app/src/components/dialog.tsx` диалог запоминает trigger, переводит фокус в первое поле, удерживает Tab/Shift+Tab внутри диалога и возвращает фокус после Escape, Cancel или закрытия.

## Regression test

| Сценарий | Ожидание | Факт | Статус |
|---|---|---|---|
| Enter на Add expense | Фокус в Description | `#description` | PASS |
| Tab | Фокус внутри диалога | Следующий элемент формы | PASS |
| Escape | Возврат на trigger | `+ Add expense` | PASS |
| Tab по кругу | Фокус не выходит | Focus trap работает | PASS |
| Данные | Без изменений | Записи не изменились | PASS |

Targeted regression выполнен в headless Microsoft Edge на `http://127.0.0.1:3000`. До исправления acceptance прошёл 24/25 сценариев; единственный FAIL относился к этому фокусу. Полный повтор acceptance после исправления заблокирован sandbox-ошибкой EPERM при доступе к `E:\Prompt`; это ограничение среды, а не ошибка приложения.

## Результат

Исправлен один подтверждённый MVP-баг без изменения бизнес-логики, данных, расчётов, маршрутов и persistence.
